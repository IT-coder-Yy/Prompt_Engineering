# 内容维护指南

新增课程时，保持“目标 → 关键概念 → 差/好 Prompt 对比 → 练习”的顺序，并使用自己的表述，不复制参考资料的大段正文。

课程按“基础入门、核心技术、研究进阶、应用实践、评测与安全”分组，维护 `lib/content.ts` 中的 `track`。原有课程的 `slug` 应保持稳定，避免破坏外部链接；课程数、时长与编号由页面自动统计。

每课必须提供 `sources`，包含实际阅读过的章节标题与原文 URL，优先引用具体章节。主要参考 [DAIR.AI 的 Prompt Engineering Guide](https://www.promptingguide.ai/zh)，已于 2026-10-12 核对本轮引用；中文页缺失时使用已核实的英文页面，并在标题注明“英文”。GraphPrompt 另引用指南所链的原始论文。

页面统一显示“参考与出处”、资料核对日期，以及本站归纳、示例和工程建议的改编说明。使用 `sourceNote` 补充研究条件、历史接口或教学简化的边界；今后补充来源时同步核对 `learningReference.reviewedAt`，不要只修改日期而不重新查阅资料。

不要把历史模型、费用、限时优惠或论文基准表现写成当前服务承诺。复杂框架的教学练习要说明所需工具、训练或图片能力，不能暗示本站文本实验室已实现 RAG、Agent、代码执行或微调。模型、论文、工具、笔记本和数据集的原文目录维护在 `furtherReading`。

新增场景时必须回答：它解决什么任务、何时不适用、输入缺什么、如何隔离不可信材料、可验证的输出结构是什么、五个测试样本是什么，以及谁应当人工复核。不要提供医疗诊断、法律结论、投资决定或自动录用、付款、发送等高风险自动决策模板。

模板变量使用 `{{variable}}`，并为每项提供清楚的标签、示例与必填状态。更新内容后运行 `npm run typecheck` 和 `npm run test`。
